## Mokipra とは

Mokipra は、**AI が面接官になってリアルな面接練習ができる** Web サービスです。

就活生や転職希望者が、相手を探さずにひとりで、何度でも面接の練習をできます。
2026年9月からは、**AI参加者4名とのグループディスカッション練習**と
**エントリーシートの添削**にも対応しました。

- 音声による自然な面接体験
- AI による自動採点と改善アドバイス
- グループディスカッション練習（Pro）
- エントリーシート添削（Pro）
- 4つの面接シーンに対応
- PDF 資料の読み込み対応（Pro）

## 主な機能

### リアルな音声面接

- OpenAI の gpt-4o-mini が面接官を担当
- 音声合成による、本番に近い受け答え
- 音声入力に対応（無音・環境音は送信前に除外）
- 1回あたりの質疑応答は Free が4ターン、Pro が10ターン

### 自動採点と改善フィードバック

- 面接終了後、AI が100点満点で採点
- 「強み」「改善点」「次のステップ」を提示
- 話し方やスピードの診断も併せて表示

### グループディスカッション練習（Pro）

一人では練習しにくいグループディスカッションを、AI 参加者4名とのやり取りで再現します。

- **自分でタイミングを選んで発言する形式**
  順番は回ってきません。黙っていても議論は進み、一定時間発言しないと
  AI から話を振られます。振られてからの発言は「自発的な発言」に数えません。
- **役割を選んで練習できる**
  司会（ファシリテーター）／書記／タイムキーパー／役割なし。
  選ばなかった役割は AI 参加者が担当します。
- **5軸10段階の評価**
  参加姿勢・発言の質・他者への反応・議論への貢献・発言量のバランス。
  参加姿勢と発言量は発言ログから機械的に算出し、残る3軸を AI が判定します。
- **役割ごとの職務チェック**
  「冒頭で進め方を提案した」「発言の少ない人に振った」などを1項目ずつ
  達成／未達で判定し、未達の項目にはその場面で言うべきだった台詞を提示します。
- **議論の長さと雰囲気を選択**
  10〜50ターン、厳格／標準／緩いの3種類。企業ごとの選考時間や温度感に合わせられます。
- **お題のランダム生成**
  具体的／抽象的、業種指定に対応。実際に出題されたお題を自分で入力することもできます。

### エントリーシート添削（Pro）

設問の種類ごとに評価軸を変えて添削します。ガクチカ・志望動機・自己PR など、
7種類の設問それぞれに固有の5軸を用意しています。

- **機械的なチェックと AI の講評を分離**
  字数、数字の有無、抽象語の多さ、冗長表現、「私は」の回数は
  AI を介さず決定的に算出します。ぶれる必要のない項目をぶれさせないためです。
- **書かれていないことを問う**
  入力後すぐに添削するのではなく、文章に書かれていない前提を
  3つ質問してから結果を出します。
- **代筆はしません**
  全文の書き換えは行わず、埋めるべき箇所を〔角括弧〕で示します。
  AI が書いた文章は面接の深掘りで破綻しますし、選考で禁止する企業も増えています。

### 複数のシチュエーション

- アルバイト面接
- 新卒採用面接
- ITエンジニア採用面接
- 大学院・推薦入試面接

### 書類を踏まえた面接（Pro）

- PDF を読み込んで、内容に基づいた面接が可能
- 研究計画書や志願理由書にも対応
- 面接官の性格（標準／優しい／超厳格）の切り替えにも対応

## プラン・価格

| プラン | 月額 | 1日の回数 | 1回のターン数 | グループディスカッション | ES添削 | PDF読み込み |
|--------|------|-----------|---------------|--------------------------|--------|-------------|
| **Free** | 無料 | 1回 | 4ターン | − | − | − |
| **Pro** | ¥480 | 5回 | 10ターン | ○ | ○ | ○ |

決済は Stripe。解約はアプリ内から Stripe カスタマーポータルを開いて行えます。
解約後も、支払い済みの期間が終わるまでは Pro の機能を利用できます。
期間終了時に webhook 経由で自動的に Free へ戻ります。

> 旧 Max プラン（¥980）は廃止しました。コードには、過去の契約が残っていた場合に
> 備えた判定だけが残っています。

## 今すぐ試す

### ブラウザで体験

[Mokipra を開く](https://app.mokipra.jp)

メールアドレスの登録のみで始められます。クレジットカードは不要です。

### ローカルで開発

```bash
git clone https://github.com/koba0605/Mokipra.git
cd Mokipra

pip install -r requirements.txt

streamlit run app.py
```

`.streamlit/secrets.toml` に以下を設定してください。

```toml
# 必須
OPENAI_API_KEY      = "sk-..."
SUPABASE_URL        = "https://xxxx.supabase.co"
SUPABASE_KEY        = "..."
STRIPE_SECRET_KEY   = "sk_test_..."
STRIPE_PRICE_ID_PRO = "price_..."
APP_URL             = "http://localhost:8501"

# 任意（未設定でも動作する）
GOOGLE_TTS_API_KEY  = "..."                         # 音声合成の第一候補
ELEVENLABS_API_KEY  = "..."                         # 音声合成の第二候補
WEBHOOK_PING_URL    = "https://..."                 # webhook サービスの事前起動先
MAINTENANCE_MODE    = "false"
GD_OPEN_TO_FREE     = "false"                       # GD を一時的に Free へ開放する検証用
TEST_PRO_EMAILS     = "a@example.com,b@example.com" # 決済を通さず Pro を検証する用
```

webhook サーバー（`webhook_server.py`）は別の環境変数を使います。

```
STRIPE_SECRET_KEY
STRIPE_WEBHOOK_SECRET
SUPABASE_URL
SUPABASE_SERVICE_ROLE_KEY
ALLOW_TEST_MODE            # 既定は未設定。検証専用サービスでのみ true にする
```

## 構成

```
mokipra.jp        →  静的HTMLのランディングページ（Cloudflare Pages）
app.mokipra.jp    →  Streamlit アプリ本体（Render / Starter）
webhook           →  Stripe イベント受信用の FastAPI（Render / Free）
```

ランディングページを分離しているのは、Streamlit が SPA のため
Googlebot がレンダリングを完了できず、検索結果に本文が表示されなかったためです。
LP を素の HTML にすることで、meta タグ・構造化データ・本文をすべて制御できます。

### ファイル構成

| ファイル | 役割 |
|----------|------|
| `app.py` | アプリ本体。認証、面接、採点、決済、画面遷移 |
| `gd.py` | グループディスカッション機能。`app.py` から `gd.render()` で呼び出す |
| `es.py` | エントリーシート添削機能。`app.py` から `es.render()` で呼び出す |
| `stt.py` | 音声認識の共通処理。無音判定とモデルのフォールバック |
| `webhook_server.py` | Stripe webhook（昇格・更新・解約の反映） |
| `patch_meta.py` | 起動時に Streamlit の `index.html` へ meta タグを注入 |
| `.github/workflows/` | Supabase のキープアライブと暗号化バックアップ |

## 技術スタック

### フロントエンド
- **Streamlit** — アプリのUI
- **Cloudflare Pages** — ランディングページのホスティング
- **Cloudflare DNS** — ドメイン管理

### バックエンド
- **Render** — Streamlit アプリ（Starter）と webhook サーバー（Free）のホスティング
- **FastAPI** — Stripe webhook の受信

### データベース・認証
- **Supabase** — PostgreSQL + 認証
- RLS（行レベルセキュリティ）でユーザーごとにデータを分離

### AI・音声技術
- **言語モデル** — gpt-4o-mini（面接AI・採点・GD・ES添削）。全プランで共通
- **音声認識** — `gpt-4o-transcribe` を第一候補とし、失敗時は `whisper-1` にフォールバック
- **音声合成** — Google Cloud TTS（ja-JP-Neural2-C）→ ElevenLabs → OpenAI TTS の順に試行

### 決済
- **Stripe** — サブスクリプション決済
- Checkout 画面で利用規約への同意を取得（同意記録は Stripe 側に残る）
- カスタマーポータルから、ユーザー自身が解約・支払い方法の変更を行える

### 運用
- **GitHub Actions** — Supabase のキープアライブ（週2回）と、
  GPG で暗号化した `pg_dump` の週次バックアップ
- **Google Search Console** — 検索パフォーマンスの計測
- **A8.net** — アフィリエイト広告（無料プランのみ表示）

## 音声入力の設計

音声認識は、文字起こしの精度そのものより **「話していないことを出力しない」** ことを
優先して組んであります。

無音のまま送信すると、モデルが文脈から尤もらしい一文を生成してしまう現象が起きるためです。
対策として、API に送る前に波形を調べ、以下を満たさない音声は破棄します。

- 録音長が 0.6 秒以上であること
- 全体の RMS が閾値以上であること
- 有声と判定されるフレームの比率が一定以上であること

また、認識精度を上げるためのヒントは散文ではなく **固有名詞の列挙**に限定しています。
散文のヒントを渡すと、それ自体が無関係な発話を生成する誘因になることを確認したためです。

## Stripe 連携の設計

webhook は3つのイベントを処理します。

| イベント | 処理 |
|---|---|
| `checkout.session.completed` | Pro へ昇格 |
| `invoice.payment_succeeded` | 更新のたびにプランを再設定（ズレの自己修復） |
| `customer.subscription.deleted` | Free へダウングレード |

### 設計上の判断

- **`subscription_data.metadata` に `user_id` を明示的に渡す**
  Checkout Session の `metadata` は Subscription オブジェクトに自動継承されません。
  これを怠ると、解約時にどのユーザーか特定できなくなります。

- **更新イベントでプランを入れ直す**
  何らかの理由でプランが Free に落ちると、課金が続いていても自動では戻りませんでした。
  更新のたびに再設定することで、ズレが次の請求で自己修復します。

- **テストモードのイベントは拒否する**
  イベントの `livemode` フラグを見て、サンドボックス由来のイベントが
  本番データベースに触れないようにしています。

- **ユーザーIDが取れなかった場合は必ずログに残す**
  昇格・解約のいずれも、`user_id` が欠落したまま黙って失敗すると
  「課金されたのに機能が使えない」状態に気づけません。

- **決済リンク生成時に webhook サービスを起こしておく**
  webhook は Render の無料プランで動いており、15分で停止します。
  眠ったままだと初回配信がタイムアウトするため、イベントが来ると分かっている
  タイミングで事前に起動させています。

## セキュリティ

- **認証** — Supabase Auth によるメールアドレス・パスワードログイン
- **データ分離** — RLS により、ユーザーは自分のデータのみアクセス可能
- **APIキー管理** — 環境変数と Streamlit Secrets で管理。リポジトリには含めない
- **XSS対策** — ユーザー入力と LLM 出力の両方を、HTML 出力前にエスケープ
- **プロンプトインジェクション対策** — ユーザー入力をタグで区切り、
  指示ではなくデータとして扱うよう明示。入力長も制限
- **選択肢の入力制限** — 自由入力を受け付ける `st.selectbox` ではなく
  `st.pills` / `st.radio` を使い、想定外の文字列が混入する経路を塞ぐ
- **アップロードPDF** — メモリ上で処理し、保存しない。AI へ渡すのは先頭約4000文字まで
- **バックアップ** — 週次の暗号化ダンプ。公開リポジトリのため GPG（AES256）で暗号化し、
  平文は Artifact 化の前に削除する

## 開発の記録

1. **MVP 開発** — Streamlit でプロトタイプを構築
2. **データベース移行** — JSON ファイルから Supabase へ
3. **決済システム** — Stripe 導入、webhook による自動処理
4. **セキュリティ強化** — RLS 実装、キー管理の見直し
5. **Render へ移行** — 独自ドメイン（mokipra.jp）を設定
6. **SEO対応** — LP を静的 HTML として分離、Cloudflare Pages へ
7. **運用基盤** — GitHub Actions による自動バックアップとキープアライブ
8. **GD機能** — グループディスカッション練習を `gd.py` として追加
9. **ES添削機能** — エントリーシート添削を `es.py` として追加
10. **音声入力の改良** — 無音判定を `stt.py` に切り出し、未発話の生成を抑止
11. **プラン統合** — Pro / Max の2本立てを廃止し、Pro（¥480・1日5回）に一本化
12. **決済まわりの整備** — カスタマーポータルの導線を追加し、
    更新イベントの処理とテストモードの遮断を webhook に実装
